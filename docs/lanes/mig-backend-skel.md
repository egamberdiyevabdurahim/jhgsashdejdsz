## Risks / not done
- Production is at Drizzle **0038** (ddbf9d81 note); the models/baseline are at **0050** (m1 head). `alembic upgrade head` on prod refuses
  until Drizzle 0039–0050 are applied there. Any Drizzle migration before cutover = regenerate models + a new Alembic revision.
- Sign-in itself (Google, Telegram, password, CSRF, callbacks) is still Auth.js in Next.js; FastAPI only READS the cookie. `jwe.encode`
  exists and TS accepts its output, so FastAPI can mint later. Today nothing refreshes the cookie (no middleware, no /api/auth/session
  calls; route-handler auth() cannot set cookies), so a fixed 30-day expiry from sign-in is the current behaviour and reading-only keeps it.
- Same AUTH_SECRET and the same AUTH_URL scheme (https -> `__Secure-authjs.session-token`) are required in the FastAPI env, or everyone is signed out.
  With AUTH_SECRET set, next-auth beta.29 never reads AUTH_SECRET_1..3 (setEnvDefaults sets the string first); the Python side
  mirrors that (AUTH_SECRET, else NEXTAUTH_SECRET) but `jwe.decode` takes a list, ready for a rotation.
- `withStudent`'s `loadRulesSnapshot()` warm-up is not ported (no ported route reads rules). Unhandled errors answer 500 `{"error":"internal"}`
  (Next answers an empty 500). Unknown routes answer `{"error":"not found"}` (Next answers its HTML 404).
- Rate limits are per process (as Node): keep 1 worker per container.
- Docker image not built or measured here (no docker on this PC); the RAM figure is the native process.
- This worktree's node_modules lacked ts-fsrs and chess.js (stale); copied both from jg-p4g-1 (same versions) to run the TS reference.
- The workflow's shared scratchpad: I overwrote a file named `mkdb.mjs` at the scratchpad root before moving my files to `scratchpad/migbe/`;
  if another lane had a `mkdb.mjs` there, it was replaced.
