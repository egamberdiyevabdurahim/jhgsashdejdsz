## Risks / not done
- **Page weight**: the React /app HTML is 288 KB (56 KB gzip) vs 112 KB (27 KB gzip) today: App Router sends server-rendered markup
  twice (HTML + RSC payload), plus ~105 KB first-load JS. The owner's weak-phone rule (18 Oct): measure on a slow phone before cutover.
- **Bridge timing**: the old scripts now start after hydration (later than at parse time). The first paint is the server-rendered
  shell; screens the scripts build (roadmap, dome, Today rows) appear a little later than today. Not measured on a slow phone.
- **Paint history at the sub-pixel**: a composited layer keeps its first raster's phase; with parts still built after the first paint, a
  phone-view case at 1440 can differ by ~0.01 % run to run (score bubbles, roadmap eye). The gate's re-raster number separates it.
- **`head` in the boot is transitional**: renderPage's runtime-tag selection (pages.ts, ~150 lines of switches) is front-end logic
  living in the backend; port it to frontend/lib (boot carrying the switches) before FastAPI, so FastAPI serves data only.
- Not done: parent apps (Stage A ~1–2 h each: boot route for parents with the `fill` + renderPage's hello/road-title/Oʻzbekcha replacements
  as props), any engine-coupled screen (003/004/006/023), /welcome, /link, /signout, /study, /pay pages (they fall through to the
  current app), the Telegram/Google buttons (off in this dev env; wired as today).
- Sign-in through the React page ends on AUTH_URL's origin (Auth.js redirect): in dev that is the current app (3234). At cutover AUTH_URL
  is the public origin, as today.
